# طلب تطوير رقم (1)

# إنشاء وحدة التكامل مع هيئة الزكاة والضريبة والجمارك (ZATCA Integration Center)

## الهدف

إنشاء وحدة مستقلة داخل النظام مسؤولة عن جميع وظائف الفوترة الإلكترونية والربط مع هيئة الزكاة والضريبة والجمارك، بحيث تكون قابلة للتطوير والصيانة دون التأثير على بقية أجزاء النظام.

---

# أولاً: هيكل الوحدة

يتم إنشاء قائمة رئيسية جديدة باسم:

**مركز التكامل مع هيئة الزكاة والضريبة والجمارك**

وتتكون من الأقسام التالية:

1- لوحة التحكم

2- إعدادات البيئة

3- إدارة الأجهزة

4- إدارة الشهادات

5- إدارة مفاتيح التشفير

6- التحقق من XML

7- إنشاء CSR

8- تسجيل الجهاز

9- إدارة CSID

10- اختبار الاتصال

11- إرسال الفواتير

12- سجل الإرسال والاستقبال

13- سجل الأخطاء

14- أدوات التشخيص

15- التقارير والإحصائيات

---

# ثانياً: لوحة التحكم

تعرض الحالة الحالية للنظام:

* حالة الاتصال بالهيئة.
* البيئة الحالية (Sandbox / Production).
* عدد الأجهزة.
* عدد الشهادات.
* عدد الفواتير المرسلة.
* عدد الفواتير المقبولة.
* عدد الفواتير المرفوضة.
* آخر عملية إرسال.
* آخر عملية مزامنة.
* حالة خدمة الهيئة.

---

# ثالثاً: إعدادات البيئة

إضافة شاشة مستقلة تحتوي على:

## بيئة التشغيل

Sandbox

Production

ويجب أن يكون تغيير البيئة من الإعدادات فقط.

لكل بيئة يتم حفظ:

* API Base URL
* OAuth URL
* Compliance URL
* Reporting URL
* Clearance URL
* الوثائق الخاصة بها
* حالة الاتصال

ويجب أن يستطيع النظام التبديل بين البيئتين دون تعديل الكود.

---

# رابعاً: إدارة الأجهزة (EGS)

إنشاء شاشة لإدارة جميع أجهزة الفوترة الإلكترونية.

لكل جهاز يتم حفظ:

* اسم الجهاز.
* Device ID.
* UUID.
* الرقم التسلسلي.
* الفرع.
* المستخدم.
* حالة الجهاز.
* تاريخ التسجيل.
* آخر اتصال.
* بيئة التشغيل.
* CSID الحالي.

الوظائف:

* إضافة جهاز.
* تعديل جهاز.
* إلغاء جهاز.
* إعادة تسجيل.
* اختبار الجهاز.

---

# خامساً: إدارة الشهادات

إنشاء شاشة مستقلة تحتوي على:

* CSR.
* Private Key.
* Public Certificate.
* Secret.
* CSID.
* إصدار الشهادة.
* تاريخ انتهاء الشهادة.
* حالة الشهادة.

الوظائف:

* إنشاء شهادة.
* تجديد الشهادة.
* إلغاء الشهادة.
* تصدير الشهادة.
* استيراد الشهادة.
* نسخ البيانات.

---

# سادساً: إنشاء CSR

يقوم النظام تلقائياً بإنشاء:

Certificate Signing Request

مع تعبئة جميع بيانات المنشأة والجهاز حسب مواصفات الهيئة.

ويتم حفظ نسخة داخل قاعدة البيانات.

---

# سابعاً: تسجيل الجهاز

يوفر النظام معالجاً (Wizard) من عدة خطوات:

الخطوة الثانية

اختيار الفرع.

الخطوة الثالثة

اختيار الجهاز.

الخطوة الرابعة

إدخال OTP الصادر من منصة فاتورة.

الخطوة الخامسة

رفع CSR.

الخطوة السادسة

استلام CSID والشهادة.

الخطوة السابعة

اختبار الاتصال.

الخطوة الثامنة

اعتماد الجهاز.

# ملاحظات هندسية

* بناء الوحدة بطريقة مستقلة (Modular Architecture).
* جميع روابط الهيئة تحفظ في قاعدة البيانات وليس داخل الكود.
* جميع المفاتيح والشهادات يتم تشفيرها داخل قاعدة البيانات.
* دعم كامل لـ Sandbox و Production دون تعديل الكود.
* جميع العمليات تسجل في نظام Logs.
* تصميم جميع الخدمات بحيث تكون قابلة للتوسعة مستقبلاً عند صدور تحديثات من الهيئة.
