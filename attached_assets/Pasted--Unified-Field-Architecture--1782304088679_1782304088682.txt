الموضوع: إنشاء بنية موحدة للحقول (Unified Field Architecture)

الهدف:

إنشاء بنية موحدة للحقول داخل النظام بحيث يتم تعريف الحقل مرة واحدة فقط داخل قاموس الحقول (Field Dictionary)، ثم إعادة استخدامه في:

* الشاشات.
* الروابط المحاسبية.
* القوالب والطباعة.
* التقارير.
* البريد الإلكتروني.
* رسائل الواتساب.
* التنبيهات والإشعارات.
* لوحات المعلومات (Dashboard).

بحيث يصبح كود الحقل هو المرجع الموحد داخل النظام بالكامل.

---

أولاً: قاموس الحقول (Field Dictionary)

إنشاء شاشة مستقلة باسم:

تعريف الحقول (Field Dictionary)

تحتوي على:

* كود الحقل (Field Code) — فريد ولا يتكرر.
* الاسم العربي.
* الاسم الإنجليزي.
* نوع الحقل.
* فئة الحقل.
* الحالة (نشط / غير نشط).
* نظامي / مخصص.

أنواع الحقول:

* Text
* Number
* Amount
* Date
* Time
* Boolean
* Percentage
* Quantity

فئات الحقول:

* المبيعات
* المشتريات
* العملاء
* الموردين
* المخزون
* الحسابات
* الأصول
* الموارد البشرية
* النظام
* أخرى

أمثلة:

NETSALES = صافي المبيعات

TAX = الضريبة

TOTAL = إجمالي الفاتورة

CASH = الصندوق

CUSTOMER_NAME = اسم العميل

CUSTOMER_MOBILE = جوال العميل

INVOICE_NO = رقم الفاتورة

INVOICE_DATE = تاريخ الفاتورة

---

ثانياً: ربط الحقول داخل الشاشات

عند تصميم أو تطوير أي شاشة داخل النظام:

* فاتورة المبيعات.
* فاتورة المشتريات.
* العملاء.
* الموردين.
* السندات.
* المخزون.

يتم إضافة خاصية جديدة لكل عنصر باسم:

Field Code

ويتم اختيارها من قاموس الحقول.

مثال:

حقل صافي المبيعات
Field Code = NETSALES

حقل الضريبة
Field Code = TAX

حقل الإجمالي
Field Code = TOTAL

حقل اسم العميل
Field Code = CUSTOMER_NAME

بمجرد حفظ الشاشة يصبح الحقل مرتبطاً بكود الحقل الموحد داخل النظام.

---

ثالثاً: تطوير الروابط المحاسبية

يوجد حالياً عمود باسم:

مصدر البيانات

المطلوب:

* أن يكون الاختيار من قاموس الحقول فقط.
* عدم السماح بالكتابة اليدوية.

مثال:

الحساب: الصندوق
اتجاه القيد: مدين
مصدر البيانات: CASH

الحساب: المبيعات
اتجاه القيد: دائن
مصدر البيانات: NETSALES

الحساب: ضريبة المخرجات
اتجاه القيد: دائن
مصدر البيانات: TAX

عند الترحيل:

يقوم النظام تلقائياً بقراءة قيمة الحقل المرتبط بالمستند وترحيلها للحساب المحدد.

---

رابعاً: تطوير مصمم القوالب

إضافة لوحة جانبية جديدة باسم:

الحقول المتاحة
Available Fields

يتم جلب الحقول من قاموس الحقول مباشرة.

مثال:

INVOICE_NO

INVOICE_DATE

CUSTOMER_NAME

CUSTOMER_MOBILE

NETSALES

TAX

TOTAL

عند اختيار الحقل يتم إدراجه داخل القالب تلقائياً.

مثال:

{{NETSALES}}

{{TAX}}

{{CUSTOMER_NAME}}

---

خامساً: تطوير مصمم التقارير

عند إنشاء تقرير جديد أو تعديل تقرير:

يتم اختيار الأعمدة من قاموس الحقول.

مثال:

NETSALES

TAX

TOTAL

CUSTOMER_NAME

INVOICE_DATE

ويقوم النظام بجلب البيانات تلقائياً من المستندات المرتبطة بهذه الحقول.

---

سادساً: قواعد العمل الأساسية

1- كود الحقل (Field Code) فريد ولا يتكرر على مستوى النظام بالكامل.

2- يتم تعريف الحقل مرة واحدة فقط داخل قاموس الحقول.

3- يمنع إنشاء نفس كود الحقل أكثر من مرة.

4- يمنع كتابة أسماء الحقول يدوياً داخل الروابط المحاسبية أو القوالب أو التقارير.

5- جميع عمليات الاختيار تتم من قاموس الحقول.

6- قاموس الحقول ليس مكاناً للبرمجة أو المعادلات.

7- الربط البرمجي يتم داخل الشاشات من خلال خاصية Field Code.

8- أي تطوير مستقبلي داخل النظام يجب أن يعتمد على أكواد الحقول الموحدة.

---

النتيجة المتوقعة

بمجرد تعريف الحقل:

NETSALES

مرة واحدة فقط وربطه داخل فاتورة المبيعات،

فإن نفس الحقل يصبح متاحاً تلقائياً في:

* الروابط المحاسبية.
* القوالب والطباعة.
* التقارير.
* الواتساب.
* البريد الإلكتروني.
* التنبيهات.
* لوحات المعلومات.

دون الحاجة إلى إعادة تعريفه أو برمجته مرة أخرى.
