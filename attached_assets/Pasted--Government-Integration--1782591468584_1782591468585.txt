# طلب تطوير: منظومة الربط الإلكتروني مع الجهات الحكومية (Government Integration)

## الهدف

إنشاء منظومة متكاملة داخل النظام لربط العملاء بالجهات الحكومية، بحيث تكون هيئة الزكاة والضريبة والجمارك السعودية (ZATCA) أول جهة يتم دعمها، مع تصميم المنظومة بطريقة تسمح بإضافة أي جهة حكومية أخرى مستقبلًا دون الحاجة إلى إعادة هيكلة النظام.

---

# أولاً: إنشاء وحدة جديدة داخل النظام

القائمة:

الإدارة
→ التكاملات
→ الجهات الحكومية

وتحتوي على:

* ربط هيئة الزكاة والضريبة والجمارك (ZATCA)
* سجل عمليات الإرسال
* سجل الأخطاء
* مراقبة حالة الإرسال
* إعدادات التكامل

---

# ثانياً: شاشة إعدادات الربط

* اسم المنشأة
* الرقم الضريبي (VAT Number)
* الرقم المميز (إن وجد)
* عنوان المنشأة

---

## إعدادات البيئة

* Sandbox
* Production

* إرسال تلقائي عند اعتماد الفاتورة
* إرسال يدوي

* مدة الانتظار بين المحاولات

---

## أدوات

* اختبار الاتصال

# ثالثاً: تعديل شاشة فاتورة المبيعات

إضافة تبويب جديد باسم:

"الهيئة"

* UUID
* Invoice Hash
* QR Code
* حالة الإرسال
* تاريخ ووقت الإرسال
* كود الاستجابة

* عدد محاولات الإرسال
* زر إعادة الإرسال
* زر عرض ملف XML
* زر عرض الاستجابة

تسجيل جميع العمليات:

* إنشاء XML
* التوقيع
* الاتصال بالهيئة

* UUID

* QRCode
* XMLFile

* ClearanceStatus
* ReportingStatus
* SubmissionDate
* ResponseCode
* ResponseMessage
* RetryCount

* IntegrationStatus
* IntegrationLogID

---

# ثامناً: محرك التكامل (Government Integration Engine)

إنشاء خدمة مستقلة مسؤولة عن:

* إنشاء XML
* إنشاء QR Code
* التوقيع الإلكتروني
* إرسال البيانات
* استقبال الرد
* إعادة الإرسال عند الفشل
* تسجيل جميع العمليات
* إدارة الشهادات
* التحقق من الاتصال

ويجب ألا يتم تنفيذ أي من هذه العمليات داخل شاشة الفاتورة مباشرة، وإنما من خلال محرك التكامل فقط.

---

# تاسعاً: التوسع المستقبلي

يجب تصميم المنظومة بحيث يمكن إضافة موصلات (Connectors) جديدة مثل:

* هيئة الزكاة والضريبة والجمارك (السعودية)
* الفاتورة الإلكترونية (مصر)
* أي جهة حكومية أخرى

دون تعديل منطق النظام الأساسي.

---

# عاشراً: متطلبات الجودة

* تصميم احترافي وقابل للتوسع (Scalable).
* فصل كامل بين واجهة المستخدم ومنطق التكامل.
* تسجيل جميع العمليات (Logging).
* دعم إعادة المحاولة تلقائيًا (Retry).
* معالجة الأخطاء بشكل واضح.
* الحفاظ على الأداء وعدم تعطيل اعتماد الفاتورة في حال تعذر الاتصال.
* توفير واجهات برمجية (Services) يمكن إعادة استخدامها من أي مستند داخل النظام.

## النتيجة المطلوبة

منظومة ربط حكومي احترافية تضاهي الأنظمة العالمية، وتسمح لأي عميل بتفعيل الربط باستخدام بياناته وشهاداته الخاصة، مع إمكانية إضافة جهات حكومية أخرى مستقبلًا دون الحاجة إلى إعادة تصميم النظام.
