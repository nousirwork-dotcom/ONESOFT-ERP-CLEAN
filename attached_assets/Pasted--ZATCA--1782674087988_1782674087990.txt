# تطوير شاشة الربط مع هيئة الزكاة والضريبة (ZATCA)

## الهدف

شاشة الربط ستكون جزءًا من البرنامج الأساسي، ولكن يتم تفعيلها فقط للعملاء الذين يشترون خدمة الربط مع الهيئة. لذلك يجب أن تكون المنظومة مناسبة لهذا السيناريو.

---

# أولاً: نظام إظهار الشاشة

* شاشة الربط موجودة داخل البرنامج.
* يمكن إظهارها أو إخفاؤها حسب ترخيص العميل أو إعدادات النظام.
* إذا كانت الخدمة غير مفعلة فلا تظهر القائمة للمستخدم.
* عند تفعيل الخدمة تظهر جميع شاشات الربط تلقائيًا.

---

# ثانياً: صلاحيات المستخدمين

إضافة صلاحية جديدة باسم:

**إدارة الربط مع هيئة الزكاة**

هذه الصلاحية تسمح فقط للمطور أو الدعم الفني بالدخول إلى:

* إعدادات الربط.
* إدارة الشهادات.
* تسجيل المنشأة.
* اختبار الاتصال.
* تعديل بيانات الربط.
* تجديد الشهادات.

أما المستخدم العادي فلا يرى إلا:

* حالة الربط.
* لوحة المتابعة.
* الفواتير الإلكترونية.
* سجل الإرسال (حسب الصلاحيات).

---

# ثالثاً: تحسين شاشة الإعدادات

إزالة الحقول التالية من واجهة المستخدم العادي:

* Secret Key
* API URL

ويتم التعامل معها داخليًا بواسطة النظام أو من خلال شاشة خاصة بالمطور.

إذا احتاج المطور إلى إدخال بيانات حساسة، فلا تظهر إلا عند تسجيل الدخول بحساب يملك صلاحية "إدارة الربط مع هيئة الزكاة".

---

# رابعاً: إضافة معلومات الخدمة

داخل شاشة الإعدادات يتم إضافة قسم جديد باسم:

**حالة خدمة الربط**

ويحتوي على:

* حالة الخدمة (مفعلة / غير مفعلة)
* تاريخ التفعيل
* اسم الفني الذي قام بالتفعيل
* آخر تحديث للإعدادات
* آخر اختبار اتصال

---

# خامساً: تحسين لوحة التحكم

إضافة بطاقات معلومات تعرض:

* حالة الاتصال بالهيئة
* حالة الشهادة
* تاريخ انتهاء الشهادة
* آخر اتصال ناجح
* عدد الفواتير المرسلة
* عدد الفواتير المقبولة
* عدد الفواتير المرفوضة
* عدد الفواتير المعلقة

---

# سادساً: تحسين شاشة الفواتير

إضافة الأعمدة التالية:

* UUID
* Invoice Hash
* Clearance Status
* Reporting Status
* وقت الإرسال
* آخر محاولة
* عدد المحاولات
* سبب الرفض

وإضافة الأزرار التالية:

* إعادة إرسال
* عرض XML
* عرض استجابة الهيئة

---

# سابعاً: سجل العمليات

إضافة إمكانية البحث والتصفية حسب:

* التاريخ
* رقم الفاتورة
* المستخدم
* نوع العملية
* حالة العملية

وإمكانية تصدير السجل إلى Excel وPDF.

---

# ثامناً: سجل الأخطاء

إنشاء شاشة مستقلة تحتوي على:

* التاريخ
* رقم الفاتورة
* كود الخطأ
* وصف الخطأ
* تفاصيل الاستجابة
* اسم المستخدم
* زر إعادة الإرسال

---

# تاسعاً: مراقبة الشهادة

إضافة تنبيهات تلقائية عند قرب انتهاء الشهادة:

* قبل 30 يومًا.
* قبل 15 يومًا.
* قبل 7 أيام.

مع ظهور إشعار داخل النظام.

---

# عاشراً: الأمان

* تشفير جميع البيانات الحساسة داخل قاعدة البيانات.
* عدم إظهار Secret Key بعد حفظه.
* عدم تسجيل البيانات السرية داخل Logs.
* عدم السماح لأي مستخدم غير مخول بالوصول إلى إعدادات الربط.

---

# الحادي عشر: التصميم المستقبلي

يجب تصميم هذه المنظومة بحيث تصبح جزءًا من منصة "التكاملات الحكومية"، حتى يمكن مستقبلاً إضافة جهات أخرى مثل:

* الفاتورة الإلكترونية المصرية.
* أي هيئة حكومية أخرى.

دون الحاجة إلى إعادة تصميم النظام.

---

# الهدف النهائي

أريد أن تكون شاشة الربط مع هيئة الزكاة والضريبة جزءًا احترافيًا من OneSoft ERP، يمكنني تفعيلها أو إخفاءها حسب ترخيص العميل، مع فصل كامل بين صلاحيات العميل وصلاحيات المطور، بحيث أتولى أنا عملية الربط والتفعيل، بينما يستخدم العميل المنظومة بسهولة وأمان دون الوصول إلى البيانات أو الإعدادات الحساسة.
